## Server mit einem Befehl installieren

Voraussetzung: Linux mit Docker Engine ≥ 24.

```bash
sudo docker run --rm -it \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/estrichone:/opt/estrichone \
  ghcr.io/florians25/estrichone-installer:0.1.0-preview.3
```

Der Installer fragt Adresse (Domain oder IP) und Firmennamen ab, startet Datenbank, API, Weboberfläche und Sicherung
und zeigt am Ende das **Backup-Passwort** (bitte außerhalb des Servers aufbewahren) und den **Einrichtungscode**.
Dann `https://<adresse>:8143` öffnen, „Jetzt einrichten“ wählen und den ersten Administrator anlegen.

| Port | Zweck |
|---|---|
| 8143 | HTTPS – Weboberfläche und API |
| 8181 | HTTP – leitet auf 8143 weiter |

- Bei einer IP-Adresse stellt der Server ein eigenes Zertifikat aus: Der Browser warnt einmal, die Android-App
  akzeptiert es nicht. Für ein gültiges Zertifikat eine Domain nutzen und am Router 80 → 8181 und 443 → 8143
  weiterleiten.
- Aktualisieren: denselben Befehl mit der neuen Versionsnummer ausführen – Daten bleiben erhalten.
- Andere Ports: `-e ESTRICHONE_HTTP_PORT=… -e ESTRICHONE_HTTPS_PORT=…`

## Dateien

| Datei | Inhalt |
|---|---|
| `EstrichONE-Setup-….exe` | **Windows-Installationsprogramm**: Startmenü, optional Desktopsymbol, Deinstallation über „Apps“. Ohne Administratorrechte installierbar. |
| `EstrichONE-Windows-x64-….zip` | Dieselbe Windows-App ohne Installation (entpacken, `EstrichONE.exe` starten) |
| `EstrichONE-Android-….apk` | Android-App (nur online; Offline-Betrieb, Kamera und Poolgeräte folgen) |
| `EstrichONE-iOS-Xcode-Projekt-….zip` | Xcode-Projekt: `ios/EstrichONE.xcodeproj` in Xcode 26 öffnen, unter *Signing & Capabilities* das eigene Team wählen, auf dem iPhone ausführen |
| `EstrichONE-Server-….tar.gz` | Quellcode-Paket für die Installation ohne vorgefertigte Images (`deploy/README.md`) |

## Funktionsumfang

- **Web:** Bauakten wie Estrich Web (Kopfaktionen, Hinweise, Kontakte, Notizen mit Verlauf, Fotos/Videos/Dokumente,
  Tagesübersicht, Erstbegehung, Räume & Flächen, Aufgaben & Mängel, Material mit Bedarfsrechnung), Baustellenkarte,
  Kolonnenplanung (Tag/Woche/Monat, Baustellen-Vorrat, Ziehen und Ablegen), Arbeitsplan, Anrufe und Anfragen mit
  Telefon-Schnellerfassung, Tagesübersicht, Bestellungen mit Bestellschein, Materialstamm, Lieferanten, Kunden,
  Benutzer und Rollen, Geräte, Helpdesk, Sicherung, Protokoll, Firmendaten.
- **Windows:** Ribbon, Suche (Strg+K), Tagesübersicht, Bauakten, Bauakte mit Reitern, Kolonnenplanung (Woche),
  Anrufe mit Schnellerfassung, Bestellungen, Helpdesk; Verwaltung öffnet bewusst das Web.
- **Android:** Ersteinrichtung mit Einrichtungscode und Gerätefreigabe, Heute (Mein Einsatz), Bauakten mit
  Schnellanlage, Bauakte mit Hinweisen, Notizen, Aufgaben/Mängeln, Anrufen und Route, Problem melden.
- **iOS:** offline-fähig mit Synchronisation, Kamera, Poolgeräten mit PIN, Bautagebuch und Prüfungen.

## Bekannte Grenzen

- Windows-Installationsprogramm und App sind nicht signiert: SmartScreen warnt („Weitere Informationen“ →
  „Trotzdem ausführen“).
- Android ohne Offline-Betrieb und ohne Fotos; Testversion mit dem Debug-Schlüssel signiert.
- Docker-Images nur für x86-64 (amd64).
- iOS-UI-Tests: je Lauf sind 8 von 9 grün; ein wechselnder Test scheitert in der CI noch zeitweise an einem
  Zeitproblem des Simulators. Die Kern-Tests gegen den echten Server sind grün.
