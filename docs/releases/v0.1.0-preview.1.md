## Server starten

Voraussetzung: Linux mit Docker Engine ≥ 24 (Compose-Plugin) und eine Domain, die auf den Server zeigt (Ports 80 und
443 offen) – Caddy holt das Zertifikat automatisch. Mit der Adresse `localhost` lässt sich nur auf demselben Rechner im
Browser testen; Telefone und andere PCs brauchen die Domain.

```bash
tar xzf EstrichONE-Server-v0.1.0-preview.1.tar.gz
cd EstrichONE-Server-v0.1.0-preview.1/deploy
sudo ./setup.sh                    # Adresse und Firmenname, erzeugt .env mit sicherem Passwort
sudo docker compose up -d --build
sudo docker compose logs api | grep Einrichtungscode
```

Dann im Browser die Adresse öffnen, „Jetzt einrichten“ wählen und mit dem Einrichtungscode den ersten
Administrator anlegen.

## Apps verbinden

- **Windows:** ZIP entpacken, `EstrichONE.exe` starten, Serveradresse und Anmeldung eingeben. Windows SmartScreen
  warnt, weil die Testversion nicht signiert ist („Weitere Informationen“ → „Trotzdem ausführen“).
- **Android:** APK auf das Telefon laden und „Unbekannte Apps installieren“ für den Browser bzw. Dateimanager
  erlauben. Ohne Einrichtungscode muss das Gerät im Web unter *IT Center → Geräte* freigegeben werden; einen Code
  erzeugt man dort mit „Gerät einrichten“. Die App verlangt HTTPS.

- **iOS:** ZIP auf dem Mac entpacken, `ios/EstrichONE.xcodeproj` mit Xcode 26 öffnen, unter *Signing & Capabilities*
  das eigene Team wählen (ein kostenloses Apple-Konto genügt für eigene Geräte) und auf dem iPhone ausführen.

## Bekannte Grenzen

- Android ohne Offline-Betrieb und ohne Fotos; Poolgeräte nur in iOS.
- Windows-App: Planen per Ziehen und Anlegen von Bestellungen im Browser.
- iOS-UI-Tests: je Lauf sind 8 von 9 grün; ein wechselnder Test scheitert in der CI noch zeitweise daran, dass der
  Simulator eine Schaltfläche kurz nach dem Start als nicht antippbar meldet. Die Kern-Tests gegen den echten Server
  sind grün.
- Testpakete sind nicht signiert (Windows) bzw. mit dem Debug-Schlüssel signiert (Android).
